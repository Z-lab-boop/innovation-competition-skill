# Innovation and Entrepreneurship Competitions

## Core principle

Build every deliverable from the same verified evidence base and the current official rules. A persuasive story may organize evidence; it must never replace it.

## Required workflow

1. **Lock the competition context.** Identify competition name, year, organizer, track/category, stage, institution, deadline, eligibility, file limits, templates, scoring rubric, and required deliverables.
2. **Verify current rules.** Find the current official organizer notice, rulebook, rubric, and templates. Record source URL, title, publication date, and access date. If they cannot be found, mark all rule-dependent guidance `provisional` and request the notice instead of inventing details. Read [references/competition-routing.md](references/competition-routing.md).
3. **Inventory evidence.** Classify every important claim as verified, user-asserted, planned/forecast, or missing. Read [references/evidence-and-claims.md](references/evidence-and-claims.md) before drafting claims.
4. **Create one competition brief.** Define the problem, target user, solution, innovation, evidence, market, business model, implementation, team, impact, risks, financial assumptions, and source/evidence IDs. This is the single source of truth for all deliverables.
5. **Map evidence to the rubric.** For each scoring item, link the intended claim, supporting evidence, deliverable location, and remaining gap. Do not hide a missing hard gate behind visual polish.
6. **Produce only requested deliverables.** Use [references/deliverables.md](references/deliverables.md) for the default structure and route to the specialized skills below.
7. **Run consistency and submission QC.** Read [references/judging-and-qc.md](references/judging-and-qc.md), fix discrepancies, then report pass items, blockers, assumptions, and actions requiring the user.

## Output contract

Lead with:

1. **Submission status:** competition context and whether current official rules are verified.
2. **Evidence status:** verified claims, unverified user claims, forecasts, and missing proof.
3. **Deliverables:** completed or proposed files, all tied to the competition brief.
4. **Rubric coverage:** strengths, gaps, and hard blockers.
5. **Next actions:** owner, evidence needed, and deadline.

## Non-negotiable boundaries

- Never fabricate or inflate patents, software copyrights, papers, awards, users, contracts, partners, orders, revenue, test results, market data, or team credentials.
- An application is not a grant; an intent letter is not a sale; a pilot is not scaled adoption; a prototype is not a validated product.
- Label forecasts and market estimates with assumptions, scenario, source, and date.
- Treat personal data, partner authorization, intellectual-property permissions, and organizer templates as hard gates.
- “冲刺”, “竞争力强”, or “容易获奖” are positioning judgments, never award guarantees.
- Preserve editable source files and a claim-to-evidence ledger so plan, deck, poster, finance, and defense answers remain consistent.
